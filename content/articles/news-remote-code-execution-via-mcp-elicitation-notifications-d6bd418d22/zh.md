---
title: "Microsoft 称 VS Code 已修复 MCP 通知中的代码执行漏洞"
dek: "公告将早于 1.145.3 的 VS Code 版本列为受影响版本。攻击需要恶意的已连接 MCP 服务器，并诱使用户点击特制通知链接。"
---

Microsoft 于 2026 年 11 月 10 日发布 VS Code 安全公告，披露模型上下文协议（MCP）信息征询请求在回退通知路径中的代码执行漏洞。公告编号为 GHSA-66hq-jw93-462h，将早于 1.145.3 的版本列为受影响版本，将 1.145.3 列为已修补版本。漏洞编号为 CVE-2026-120779，严重程度为高，CVSS 评分为 8.3。[^1]

据公告，服务器控制的消息内容可能被解释为可交互的 VS Code 命令链接。用户一旦点击特制通知中的链接，恶意 MCP 服务器就可能借此触发命令执行。公告明确指出，攻击者需要控制一个已连接的 MCP 服务器，并诱使用户点击恶意链接；所描述的攻击需要用户交互。[^1]

Microsoft 表示，修复从 VS Code 1.145.3 开始提供：将信息征询消息按字面文本呈现，并在显示前验证请求载荷。公告列出的补丁为 305e248 和 e3a4962。其临时应对建议是只连接可信的 MCP 服务器，并且不要点击不可信服务器生成的通知链接。[^1]

:::analysis
这一问题涉及 T5（智能体层）和 T2（运行时层）：MCP 服务器提供内容，VS Code 负责解释和显示，公告描述的风险出现在服务器文本被转化为可执行命令入口的环节。用户和运维人员应核对实际为每位用户提供服务的版本，确认是否已采用公告建议的修复版本 1.145.3，并检查连接了哪些 MCP 服务器、是否可信。[^1] 这里关系到的可核验属性是**可识别性**：如果实际为用户提供服务的确切版本和配置有记录且可查，用户就能判断自己是否曾处于受影响的环境；这些记录本身不能确认攻击是否发生。
:::
