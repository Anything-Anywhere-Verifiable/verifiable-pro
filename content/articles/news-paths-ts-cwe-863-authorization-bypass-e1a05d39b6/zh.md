title: "MCP Inspector 安全公告报告 Windows 守护进程授权绕过漏洞"
dek: "安全公告将 2.10.0 至 2.14.0 列为受影响版本，将 2.15.0 列为已修复版本，并描述了针对 Windows 可预测命名管道的本地攻击。"
---

2026 年 11 月 12 日，Model Context Protocol Inspector 仓库发布的一则安全公告报告了 Windows 守护进程通信路径中的授权绕过漏洞。公告将 npm 包 `@modelcontextprotocol/inspector` 的 2.10.0 至 2.14.0 版本列为受影响版本，将 2.15.0 列为已修复版本。[^1]

公告称，`getDaemonSocketPath` 的 Windows 分支根据解析并转为小写的守护进程目录路径，计算哈希并生成命名管道名称。公告称该名称可以预测，本地攻击者可以抢先创建管道，冒充守护进程，并截获客户端发送的持有者令牌。公告还称，Windows 上的 `assertTrustedPrivateRoot` 会直接返回，不验证所有权或访问控制。[^1]

公告提出的修复措施包括：随机生成管道名称并将其写入令牌文件，验证守护进程目录的 Windows 访问控制和所有者，拒绝某些已存在的管道实例，并在客户端发送令牌前验证守护进程身份。公告页面将漏洞评级为 Moderate，CVSS 分数为 5.0；公告正文则将严重程度称为 HIGH。保存的来源没有解释这一差异。[^1]

:::analysis
该问题位于运行时层（runtime，T2）：相关信任边界涉及软件运行时客户端与守护进程之间的通信。核查者可以通过公告了解所列的受影响版本和已修复版本，但仍需信任部署方提供的信息，或独立核查实际版本和配置。这里涉及的可核验属性是可识别性：如果为某个用户提供服务的确切版本和配置有记录且可核查，该用户就能判断自己是否曾处于公告描述的受影响环境中。用户和运营者应检查自身版本及 Windows 部署配置，包括是否运行了公告列出的已修复版本 2.15.0；仅凭公告无法确定某个具体部署已经修复。[^1]
:::
