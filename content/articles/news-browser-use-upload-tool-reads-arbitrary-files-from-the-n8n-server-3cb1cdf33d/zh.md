dek: "10 月 28 日发布的公告称，Browser Use 上传工具可读取服务器文件，并列出三个修复版本。是否受影响取决于部署版本、功能配置和用户权限。"
---

n8n 于 2026 年 10 月 28 日发布安全公告，披露 Browser Use 上传工具存在漏洞，可泄露 n8n 服务器进程有权读取的文件。公告将 GHSA-9qx8-fhxv-w794 评为中等严重程度，通用漏洞评分系统（CVSS）得分为 6.0，并称 2.46.1、2.45.5 和 3.0.1 版本已包含修复。[^1]

据公告，`browser_upload` 接受绝对文件路径，并将其传给 Playwright。由于浏览器会话采用远程连接，Playwright 在 n8n 服务器上解析这些路径，而非在用户电脑上。已认证的成员连接自己的浏览器会话后，可以将文件内容传入助手操控的网页，再从中获取内容。只要 n8n 进程用户有读取权限，实例配置文件也在影响范围内。[^1]

利用漏洞的前提是实例通过 `N8N_INSTANCE_AI_BROWSER_USE_ENABLED=true` 显式启用 Browser Use。n8n 称，用户看到的批准提示只显示当前网页的主机名，既不展示文件路径，也不对该路径设置批准关卡。[^1]

n8n 建议升级至上述任一修复版本或后续版本。临时措施包括将该开关设为 `false` 或不设置以关闭 Browser Use、仅允许完全可信的用户访问实例，以及移除未获完全信任用户的 `global:member` 权限。公告明确指出，这些措施不能彻底消除风险。[^1]

:::analysis
问题涉及 T5（agents，智能体层）和 T2（runtime，运行时层）：前者涉及工具批准提示如何描述操作，后者涉及服务器权限允许读取哪些文件；按公告描述，用户无法依据该提示判断将访问的文件路径。这里的可核验属性是可识别性：若为用户提供服务的确切版本与配置有记录且可检查，用户就能判断自己是否曾处于漏洞影响条件之下，但这不能说明文件是否实际遭到窃取。用户和运营方应对照 n8n 列出的修复版本核对实际服务版本，并检查 Browser Use 开关、成员权限及进程可读取的文件范围。[^1]
:::
