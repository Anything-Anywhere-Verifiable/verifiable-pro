Zihou Ren、Byungchul Tak 和 Long Wang 于 2026 年 10 月 29 日向 arXiv 提交论文 REALM: Identifying Minimal Task Assets for LLM Agents。作者提出，识别并持续维护智能体完成任务所需的资源，包括执行过程中才发现的资源。论文针对的问题是：智能体获得的文件、账户和服务访问权限往往超出任务需要，提示注入可利用这些多余权限，将执行引向无关资源。[^1]

REALM 的全称是 Required Execution Assets Linked to a Mission。它将任务所需资源表示为依赖图节点，并解析资源之间的前置依赖关系。摘要称，新发现的资源通过限定来源范围的选择机制纳入，将发现资源与授权使用分开，同时保留智能体选择计算方式的自由。REALM Builder 维护选定的授权并生成 Asset Files；Partial API Manager 则在 Task Container 内向智能体提供绑定具体资源的 Partial API。[^1]

作者报告，使用 qwen3.5-flash 作为基础模型，在 AgentDyn 的 60 项正常任务和 560 个注入案例上开展评估。摘要给出的任务完成率分别为 40.0% 和 36.4%，攻击成功率（ASR）则从 16.6% 降至 0.2%。这些数字属于作者报告的评估结果；阅读摘要不能独立确认结果能否复现，也不能确认其是否适用于其他部署。[^1]

:::analysis
这项主张涉及 T6 评估层、T5 智能体层和 T2 运行时层，分别对应基准证据、任务级授权决策，以及向智能体开放资源的接口。用户和运营方在依赖该方案前，应核查自身系统选定的授权、新发现资源的授权流程，以及接口是否绑定具体资源；保存的摘要没有推荐任何修复版本。这里涉及的可核验属性是可识别性：如果实际为用户提供服务的确切版本和配置有记录且可核查，用户就能判断自己是否曾暴露于相关部署条件；该来源并未确立此类部署记录或核查机制。[^1]
:::
