title: "Agent Router 公告披露 MCP 会话跨路由复用可绕过工具授权"
dek: "公告将 1.2.0 列为受影响版本、1.2.1 列为修复版本。所述证据来自隔离的处理器测试，未测试完整网关与 OAuth 集成。"
---

Agent Router 于 2026 年 11 月 6 日发布安全公告称，在特定的混合认证配置下，跨路由复用模型上下文协议（MCP）会话，可绕过针对单个工具的 JSON Web Token（JWT）授权。公告 GHSA-72hp-5vm2-frr7 将 1.2.0 列为受影响版本、1.2.1 列为修复版本，严重程度为中等，CVSS 3.1 评分为 6.8。[^1]

该配置涉及同一 Gateway 上共用代理的两条路由：路由 A 使用 OAuth 和逐工具 JWT 规则；路由 B 不验证持有者令牌，也不设置会话主体请求头。公告称，恢复会话时，代理从会话 ID 中还原路由 A，却未将其与当前请求路由比较。随后，路由 A 的授权代码解析当前令牌时不验证签名，使伪造的权限范围声明能够通过工具授权规则。[^1]

调用者仍须持有有效的低权限账户，先在路由 A 建立会话，并能访问路由 B，同时保留会话 ID 和主体信息。后端与工具选择器仍然生效。公告称，该问题不会绕过首次 OAuth 登录，也不会授予集群管理员权限；实际影响取决于所配置工具暴露的数据与操作。[^1]

:::analysis
问题涉及 T5 agents（代理层）和 T2 runtime（运行时层）：前者的工具权限界定允许执行的操作，后者通过路由与会话处理落实权限，因此核验者仅凭受保护路由的策略，无法判断授权是否得到执行。用户与运营者应核对部署的软件包身份、是否运行公告列出的修复版本 1.2.1，以及路由是否共用所述代理并采用相应认证配置；公告的软件包字段写的是 `github.com/envoyproxy/ai-gateway`，正文则称 Agent Router。这里关系到的可核验属性是**可识别性（identifiability）**：如果为用户提供服务的确切版本与配置有记录且可检查，用户就能判断自己是否曾处于公告描述的漏洞影响条件下。[^1]
:::

:::checked
我们于 2026 年 11 月 10 日阅读了保存的 GitHub 官方安全公告《Cross-route MCP session reuse bypasses per-tool JWT authorization》。我们没有测试系统，也没有审查代码。本次阅读确认了公告所作的报告：隔离的处理器测试将请求送达本机回环后端，保存的证据没有阴性对照请求，且未测试完整的 Envoy、Kubernetes 与 OAuth 集成。1.2.1 已修复的说法仍属于公告声明。[^1]
:::
