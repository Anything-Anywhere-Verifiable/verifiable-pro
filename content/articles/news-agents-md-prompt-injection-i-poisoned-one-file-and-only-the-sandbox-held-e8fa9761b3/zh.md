---

Stackness 于 2026 年 11 月 18 日发表 Sergei Gordeichuk 的一篇报告，介绍他使用受污染的 `AGENTS.md` 文件对 Claude Code 和 OpenAI Codex 进行的测试。作者称，该文件把一个 shell 脚本包装成项目设置步骤，而脚本实际试图读取假令牌、将其发送到本机监听端口，并在仓库外写入文件。[^1]

作者报告称，Claude Code 在自动模式下的 10 次运行中有 4 次将令牌发送到了监听端口。Codex 在报告的 5 次运行中均执行了脚本，但令牌没有到达监听端口，仓库外写入也未成功。在其中能够记录结果的 3 次 Codex 运行中，脚本读取到了令牌。作者称，加入读取拒绝权限配置后，脚本未能读取令牌。[^1]

报告称，测试使用的是 macOS 上的 Claude Code 2.1.327 和 codex-cli 0.162.1。作者指出，测试只涉及一个载荷、一台 Mac、一个本机监听端口和一个 Codex 模型。他还表示，shell 沙箱设置并不覆盖所有路径：智能体自身的工具和单独配置的服务可能在该边界之外运行，允许访问的网络目标及沙箱缺陷也带来其他风险。[^1]

:::analysis
这一问题涉及智能体层 T5 和运行时层 T2：前者关系到项目文本如何影响智能体的行动，后者关系到命令权限能限制这些行动访问什么。报告中的运行结果只支持对所测配置的判断，不能说明其他部署同样受到保护。这里涉及的可核验属性是可识别性：如果向用户提供服务的确切版本和配置有记录且可供核查，用户就能判断自己是否曾暴露于所述条件。用户和运营者应检查自身的版本、沙箱和凭据读取规则，并用作者提供的金丝雀测试检查实际设置；对于 Claude Code，原文建议使用 2.1.285 或更高版本，并列出了此前的沙箱修复。[^1]
:::
