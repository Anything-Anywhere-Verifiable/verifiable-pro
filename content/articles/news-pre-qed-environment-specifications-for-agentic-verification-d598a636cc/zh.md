---

Tristan Lim 等研究者于 2026 年 11 月 11 日向 arXiv 提交了 *Pre-QED: Environment Specifications for Agentic Verification*。作者认为，使用大语言模型智能体开展验证，瓶颈已从如何生成数学证明转向应该证明什么。他们提出可执行的验证框架，目标是建模应用程序编程接口（API）的所有合法用法。[^1]

摘要批评了直接把模糊测试框架用作形式化规约的做法，并以 Anthropic 和 Theorem 的 OSS-Verify 为例，称其智能体证明的是单个测试框架不会崩溃。按照作者的解释，模糊测试框架只在一种调用上下文中执行一组 API 调用序列，因此相应的数学证明覆盖的是一个使用场景，不能据此推及整个库。这是预印本作者的判断；我们此次阅读并未独立核实 OSS-Verify 的覆盖范围。[^1]

Pre-QED 提出的工作流先从代码和文档中提取 API 使用契约，再用线性时序逻辑（LTL）排除非法调用顺序。作者称，他们将验证框架作为开源挑战发布，并指出了为其构造数学证明的难点。覆盖每一个遵守契约的客户端，是这项工作的目标；保存的摘要并未证实这一目标已经实现。[^1]

:::analysis
这一问题涉及 T6 评估层、T5 智能体层和 T2 运行时层：验证结论取决于规约、智能体对 API 契约的理解，以及实际覆盖的库使用方式。用户和运营方应核对自身的库版本、配置及允许的调用序列是否与验证对象一致；来源没有推荐任何修复版本。这里需要关注的可核验属性是可识别性：如果服务于某位用户的确切版本和配置有记录且可检查，那么在已知覆盖缺口能对应到这些记录的前提下，该用户就能判断自己是否曾受到该缺口影响。这是从规约问题推导出的运维要求，并非 Pre-QED 已展示的能力。[^1]
:::
