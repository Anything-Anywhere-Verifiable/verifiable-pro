2026 年 11 月 16 日，Hua Zhang 和 Min Jiang 提交了一篇预印本，介绍 Linglong Agent Service（agentsvc）。这是一个自托管的 HTTP 服务和可嵌入的 Python 运行时，用于协调跨执行场所运行的语言模型智能体。作者将执行位置作为与模型、工具和上下文并列的配置选项。[^1]

摘要称，父服务保留推理编排、工具描述和对话历史。每次推理请求选择一个子环境，执行文件、Shell、终端和 Model Context Protocol（MCP）操作。直接 HTTP 连接和由子环境发起的 WebSocket 隧道提供相同的应用接口，包括可移植的请求上下文和集中管理的更新。作者称，常规核心路径不需要第三方 Python 包；Windows 伪终端有一项可选依赖。[^1]

作者还将 `online_debugger` 描述为在进程尺度上分离执行场所的例子。经过插桩的程序提交异常证据，在发生问题的进程内运行仅限当前会话的检查工具，然后继续同一诊断会话。其默认提示词要求提供复现证据，表明源代码修改前测试失败、修改后测试通过。摘要称，运行时补丁激活和失败调用恢复仍未实现。[^1]

摘要报告了实现和回归测试方面的证据，并称这些证据确立了可执行的行为约定。摘要明确表示，证据不能说明系统具有性能优势，也不能说明其修复准确率或生产环境恢复能力。仅读取摘要不能独立核实所报告的测试及其结果。[^1]

:::analysis
这一设计涉及 T5 智能体层和 T2 运行时层：前者协调推理与工具使用，后者涉及执行环境和连接的选择。除非部署组件及其配置可供检查，否则用户或核验者仍需信任这些信息；摘要没有确立可独立检查特定部署的机制。这里涉及的可核验属性是可识别性：如果为某个用户提供服务的确切版本和配置已被记录且可供检查，该用户就能判断自己是否接触过特定版本或配置。用户和运维人员应检查自身部署的版本、选定的执行场所以及连接配置；来源没有推荐修复版本。[^1]
