---
title: "AWS 安全公告称 API MCP Server 存在策略绕过漏洞"
dek: "安全公告称，操作名称规范化错误可能使本地运行的服务器绕过自定义策略条目。公告建议升级并修补衍生代码。"
---

2026 年 11 月 10 日发布的一份 AWS 安全公告称，AWS API MCP Server 中的一个漏洞可能绕过自定义安全策略的部分限制。公告列出的受影响版本为 `awslabs.aws-api-mcp-server` 0.2.13 及以上、1.5.1 以下版本，并将 1.5.1 列为已修复版本。[^1]

这个开源的模型上下文协议（MCP）服务器让 AI 助手通过 AWS API 调用管理 AWS 账户。公告称，服务器在将操作名称与策略比较之前，会错误地规范化含有连续大写字母的名称。因此，`denyList` 或 `elicitList` 中针对这些操作的条目可能无法生效。[^1]

公告称，攻击者因此可能执行原本被策略禁止或要求用户确认的操作，例如创建联合身份提供商、停用多因素认证设备或删除数据库集群。漏洞利用的条件包括：服务器在本地运行，自定义策略列有受影响的操作，并且用户与 AI 助手交互。[^1]

公告称，远程 AWS API MCP Server 服务以及 `READ_OPERATIONS_ONLY` 和 `REQUIRE_MUTATION_CONSENT` 设置不受影响。公告建议升级到最新版本，并确保分叉或衍生代码纳入修复；除升级外，公告没有列出其他变通方法。[^1]

:::analysis
这一问题涉及智能体层（T5）和运行时层（T2）：助手能否调用某项操作，取决于服务器如何执行策略。用户或核查者不能仅凭策略文本就认定受影响的条目已得到执行。这里需要关注可识别性：如果为某位用户提供服务的确切版本和配置都有记录且可供检查，用户就能根据公告所列条件判断自己是否曾面临风险。运营者应核查运行版本、服务器是否在本地运行、相关自定义策略条目，以及分叉代码是否纳入修复，并遵循公告的升级建议。[^1]
:::
