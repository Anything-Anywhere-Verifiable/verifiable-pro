---
title: "Microsoft 扩展 Agent 365 的身份与活动监测功能"
dek: "Microsoft 表示，Ignite 更新让管理员能够跨平台查看更多智能体，并提供处于不同发布阶段的身份、活动和风险管控功能。"
---

Microsoft 于 2026 年 11 月 17 日宣布更新 Agent 365。该公司表示，这些更新扩大了组织跨平台及员工设备识别、监测和管理 AI 智能体的能力。公告所述功能处于不同发布阶段，包括预览版和正式发布的功能。[^1]

Microsoft 表示，接入的智能体会获得 Microsoft Entra Agent ID，管理员可借此区分智能体与人员的身份，并应用受支持的策略。该公司称，对多个合作伙伴平台的支持正在推出，预计于 12 月完成；各平台支持的功能有所不同。[^1]

该公司还表示，Microsoft Defender 和 Microsoft Entra Global Secure Access 可以发现本地智能体及其配置的 Model Context Protocol（MCP）服务器，相关信号会进入 Agent 365 注册表。Defender 的本地智能体发现功能已正式发布；网络层面和注册表中的发现功能仍在预览。单独的本地智能体身份管控功能也处于预览阶段，首批支持 GitHub Copilot CLI 和 Claude Code。[^1]

Microsoft 表示，管理员可以将智能体追踪记录导出至 Azure Monitor 和 Application Insights，按智能体或平台筛选，并选择是否包含特定提示词和回复。处于预览阶段的动态智能体风险功能会汇总运行时信号，生成随情况变化的风险等级。公告还介绍了预览中的多租户管理功能，包括跨租户比较智能体的配置和访问权限。[^1]

:::analysis
这些主张涉及智能体层（T5）和运行时层（T2）：身份信息、活动记录和运行时信号可以为运维人员提供可供检查的证据，但证据是否完整、准确，仍需在各自部署中核实。这里涉及的可核验属性是可识别性：如果记录了为某位用户提供服务的确切版本和配置，且这些记录可供核查，该用户就能判断自己是否受到某个具体问题的影响。用户和运维人员应核实自己的部署实际覆盖哪些智能体和平台、保留哪些配置及活动记录，以及启用了哪些预览或正式发布的管控功能；公告本身无法确立任何特定系统的这些情况。[^1]
:::
