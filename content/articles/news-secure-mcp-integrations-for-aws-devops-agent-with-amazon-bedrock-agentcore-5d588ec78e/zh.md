---
title: "AWS 介绍 DevOps Agent 的 MCP 安全控制"
dek: "AWS 介绍了智能体工具的直连和网关接入方式。其中一项审批控制取决于运维人员如何对工具分类。"
---

2026 年 11 月 17 日，AWS 发布指导文章，介绍如何将模型上下文协议（MCP）工具连接到其事件调查智能体 AWS DevOps Agent。文章介绍了直连 MCP 服务器，以及通过 Amazon Bedrock AgentCore Gateway 建立共享连接两种方式。AWS 表示，网关可以集中管理身份验证、策略和可观测性。MCP 为智能体在调查期间调用外部工具和数据源提供了一种方式。[^1]

在直连方式下，管理员注册服务器，并为每个智能体空间选择工具。AWS 表示，每个工具都应分类为只读、可修改或破坏性操作：只读工具运行时无需运维人员批准；调用可修改工具前，必须启用定向操作，并在聊天中获得运维人员批准；被归类为破坏性的工具不会被调用。AWS 提醒，通过 API 或命令行注册时，未分类的工具默认视为只读，因此运维人员必须对可能改变状态的工具进行分类。[^1]

使用 Gateway 时，智能体只需注册一个端点，后端服务器则配置为目标。AWS 表示，网关可以集中管理目标凭证，并通过 Cedar 策略对工具实施统一规则。文章还介绍了工具调用日志和跨组件追踪，并建议每个智能体空间只开放所需工具，优先使用只读访问，以减少提示注入风险。[^1]

:::analysis
这些控制涉及 T5 智能体层和 T2 运行时层：工具选择与分类决定智能体可以请求哪些操作，网关策略和日志则关系到请求如何被处理和记录。用户和运维人员应检查自己系统的工具允许列表、分类、凭证和网关策略；仅凭这篇文章，无法确认任何具体部署已落实这些控制。这里还涉及可识别性：如果服务某位用户的确切版本和配置有记录且可供检查，该用户就能判断自己是否受到某个具体问题的影响。文章没有指出受影响版本或修复版本，也没有确认具体部署一定留存了这些记录。[^1]
:::
